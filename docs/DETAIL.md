# Anki Assistant — 设计说明

把「资料 → 问题集 → 答案 → 卡片 → 记忆提示」做成可检查、可续跑、可回查的流程，
但不把顺序写死：工具只回答状态，决定由 Agent 与方案做。

## 能做什么

- **方案库**：方案是数据资产，不是插件代码。改方案 = 出新版本，旧版本永远保留，批次钉版本。
- **方案自带校验器**：方案目录里的 `validate.mjs` 由插件按 `quality.validator.module` 加载；
  缺模块、加载失败、异常退出都明确报错，不退回 JS 兜底。
- **批次**：一批待生产的题，逐题记录状态与失败原因；中断后接着跑。
- **资料**：PDF 按页抽文本并按坐标重建行，返回页码与行号，可直接写进定位字段。
- **写入闸门**：先出预览（规则、判重、挖空截断、方案校验器），确认后再写；写入幂等。
- **回读**：写完逐字核对字段，不一致逐条列出。
- **渲染**：按模型真实模板与 CSS 渲染正面/背面，可出 PNG（整批或逐张）、A4 PDF（三种版式），
  并能量出横向溢出供 Agent 自动修正。

## 设计取舍

| 取舍 | 理由 |
|---|---|
| 自带 AnkiConnect 薄客户端，不用 MCP | MCP 是 profile 里的一行配置，换机器就没了；写入路径不能绑在别人的配置上 |
| 不用 `storageDomain` | 需要在 profile 里配 route，desktop profile 无法从 CLI 校验；本产品数据要可读可备份 |
| 自带 PDF 行重建 | 现成插件把一页压成一行：双栏串行、表格糊、行号丢失。资料读取是核心能力 |
| 规则引擎只有 7 种 | 机械检查只挡"明显写坏"；语义正确性只能对照原文由人判断 |
| 判据归方案目录 | 方案换掉，判据一起消失；插件不替任何学科内置判据 |
| 记忆提示放在卡字段里 | 它随卡走、随卡改、随卡删；放到卡组外面必然与卡脱节 |
| 预览复现真实模板，而不是像素级截图 | 稳定、可批量、可对比；代价是模板 JS 与媒体不执行 |
| 挖空截断做成内置检查 | `^{\mathrm{T}}` 这类写法在 Anki 里同样会截断，属于跨方案通用错误 |

## 方案的生命周期

1. 随包方案（`assets/schemes/`）首次安装登记为 v1；
2. 包内 `revision` 更高时追加新版本：先快照旧正文，再刷新包内资产（正文、样卡、测试、判据）；
3. 旧版本、旧正文保留，正在跑的批次仍钉旧版本；
4. 用户自建方案只存在于数据目录，不进 npm 包；要分享用导出，要成为默认内容才放进 `assets/`。

## 缺失提示

- 读不到 PDF：提示装 `pdfjs-dist` 或先转成 `.txt`。
- 连不上 Anki：只读功能仍可用；`commit` / `verify` / `card_preview` 报错。
- 模型不存在或字段对不上：`card_write plan` 报出缺哪个字段，不静默写空。
- 方案没有任何校验规则：`validate` 与 `plan` 提示「请人工逐张核对」。
- 找不到 Edge：预览只出 HTML，不出 PNG / PDF。

## 版本

- `0.1.0`：方案库、批次、资料读取、写入闸门与回读。
- `0.2–0.3`：方案外壳变薄、外部提示词导入、派生方案与校验器接入。
- `0.4`：方案私有判据（Python 原码随方案目录）、样卡与入口级测试。
- `0.5`：数学方案、`quality.validator` 接口、卡面渲染（真实模板 / MathJax / PNG / PDF）、
  打印版式与自定义 CSS、挖空截断检查。
- 未做：任务/阶段血缘、方案候选晋升、导出/导入命令。
