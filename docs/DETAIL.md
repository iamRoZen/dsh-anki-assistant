# Anki Assistant

把「资料 → 问题集 → 答案 → 卡片 → 记忆提示」变成可检查、可续跑、可回查的流程，
但不把顺序写死：工具只回答状态，决定由 Agent 做。

## 能做什么

- **方案库**：方案是数据记录，不是代码。改方案 = 出新版本，旧版本永远保留，任务钉住版本。
- **批次**：一批待生产的题，逐题记录状态与失败原因；中断后接着跑。
- **资料**：PDF 按页抽文本并按坐标重建行，返回页码与行号，可直接写进定位字段。
- **写入闸门**：先出预览（字段规范、批内重复、Anki 已有重复），确认后再写；写入幂等。
- **回读**：写完逐字核对字段，不一致逐条列出。

## 设计取舍

| 取舍 | 理由 |
|---|---|
| 自带 AnkiConnect 薄客户端，不用 MCP | MCP 是 profile 里的一行配置，换机器就没了；插件不能把写入路径绑在别人的配置上 |
| 不用 `storageDomain` | 它需要在 profile 里配 route，而 desktop profile 无法从 CLI 校验；本产品数据要可读可备份 |
| 自带 PDF 行重建，不用现成插件 | 现成插件把一页压成一行：双栏会串行、表格会糊，行号也没了。资料读取是本产品的核心能力 |
| 规则引擎只有 7 种 | 机械检查只挡"明显写坏"；语义正确性只能对照原文由人判断 |
| 记忆提示放在卡字段里 | 它随卡走、随卡改、随卡删；放到卡组外面必然与卡脱节 |

## 缺失提示

- 读不到 PDF：提示装 `pdfjs-dist` 或先转成 `.txt`。
- 连不上 Anki：提示确认 Anki 与 AnkiConnect；此时只读功能仍可用。
- 笔记模型不存在或字段对不上：`card_write plan` 直接报出缺哪个字段，不静默写空。
