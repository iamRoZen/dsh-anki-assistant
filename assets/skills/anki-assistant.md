# Anki Assistant 制卡方法

制卡是核心：**资料 → 问题集 → 答案 → 卡片 → 记忆提示**。工具只做确定性的事（读资料、存方案、排队、校验、写入、回读），
判断留给你。

## 一、五个模块

每个模块单独可用，也能接龙；按任务跳过或关闭。

| 模块 | 接收 | 交付 | 缺什么时怎么办 |
|---|---|---|---|
| **资料整理** | 书、PDF、讲义、网页、已有笔记 | 可回读的定位（页 + 行 / URL + 段落）与要用的那几段原文 | 没有可读文本就先转换或换资料；定位不到就停下说明，不要凭印象往下做 |
| **问题集整理** | 资料、大纲、题库、学习目标 | 带稳定 id、题型、出处的题目清单 | 没有题干就自拟，并在清单里标明"自拟"；有题干就照抄，不改语序 |
| **撰写答案** | 题目 + 对应原文 | 逐条可判分的答案与每条依据 | 找不到依据就标"待补依据"，不要合成原文没有的结论 |
| **制作卡片** | 题目 + 答案（+ 方案） | 符合方案字段规范的卡片，写入后回读 | 没有方案就按已有笔记模型的字段建一份；模型字段对不上就报错，不写空 |
| **制作记忆指导** | 答案结构 + 易错点 | 卡上的记忆提示（回忆起点、递推、最易漏的一步） | 写不下说明这张卡该拆；不要用复述答案充当提示 |

组合示例：`资料整理 → 问题集整理 → 撰写答案 → 制作卡片 → 记忆指导`。
常见捷径：**题干与带出处的答案都已有时，直接从「制作卡片」开始**；只想出题时，到「问题集整理」为止。

通用说明与示例保持学科中立。医学的字段写法、数学的公式坑，属于具体方案或实践，不写在这里。

## 二、先找方案，再动手

1. `scheme list` 看有哪些方案；`scheme get id=…` 取完整规则——**含正文**（`body`）。
2. 正文是这套方法的权威文本：适用场景、资料入口、各模块怎么做、字段与卡面、检查标准、正反例、验收。
3. 没有合适方案才新建：`scheme save` 写 `status: draft`，说明为什么需要；经用户确认再 `active`。
   每次保存都是新版本，旧版本永远保留。

用户改一条规则后，怎么让新任务用上新版：`scheme save` 生成 v+1 → 之后 `batch open` 钉住的版本就是新版；
在跑的批次仍钉在旧版，需要时用 `batch open`（同名再调用）改绑到新版本。

## 三、找实践

`practice list` 列出所有实践（按主题、模块、方案筛选）；`practice get id=…` 读全文。
实践名形如 `2026-11-18-外科历年题-按样卡制表格卡`，能看出主题与做了什么。
每条实践记录：原始请求、用了哪些模块、方案版本、关键取舍、产物、核查结果。
方案正文里的 `practices` 字段会反查用过它的实践——想学"这套方案实际怎么跑"就先看实践。

## 四、资料：定位比摘要重要

- 定位写成能回查的形式：`p<PDF页>:L<行号>`，必要时补印刷页 `（印刷 p198）`。
- 取原文用 `materials`：`pages` 选页，`keyword` 只取命中行，返回的 `p31:L12` 直接进 `章节定位` / `引用`。
- 定位写不出来，就是还没真正取到原文。

## 五、答案：先成树，再压成句

1. **判根数**：缩成顶层是一个根还是两个互不依赖的根？两个就拆成两张卡。
2. **判形状**：原文是并列、分层，还是行列对照？照原文的编号走，不照好看的样子走。
3. **写骨架**：只有编号和分支名，一个内容词都不填。
4. **填内容**：每个叶子一行；单行超过 25 字，多半塞了两个判断。
5. **压缩**：删措辞，不删层级、限定语、方向、阈值。

## 六、卡片：按字段写，不按手感写

- 字段名与顺序以笔记模型为准；方案首字段是判重键。
- 方案里的规则只查机械项（挖空包裹、长度、必填、字数、Markdown）。语义对错要对照原文。
- `要点数` 这类派生字段按实际内容算，不手填；格式对不等于数对。

## 七、写入与回读

1. `batch open` 建批（钉方案版本）→ `batch put` 逐题录入 → `batch validate` 跑规则与查重。
2. `card_write plan` 出预览：可写几张、受阻原因。**把预览给用户看**。
3. 用户确认 → `card_write commit`。新增是幂等的，重跑不会重复出卡。
4. `card_write verify plan=…` 按提交时的快照回读：缺卡、缺字段、内容不符都会报。

改已有卡用 `card_write plan mode=update`（题上要有 noteId）。只有真的改到目标字段才算成功；
内容本来就一样会报"已相同"，不会假装成功。

任何时候改了草稿、方案版本或目标牌组，旧计划都会失效，必须重新 plan。

## 八、记忆提示是卡的一个字段

`role: memory` 的字段（常见是"笔记"或"背面额外"）回答**这张卡怎么背**：回忆起点、递推关系、最易漏的一步。
不是答案复述，也不是卡组外的讲解。两行以内；写不下就拆卡。

## 九、从一次操作沉淀方案

用户改卡时体现出新写法：先 `scheme save` 一份 `status: draft`，`changeWhy` 写清来源；
经确认再 `active`。不要直接改正在用的方案版本。

## 十、边界

- 不替用户点评分、不改调度。
- 不猜字段；模型字段对不上就报错。
- 删除只走用户明确要求；批量删除先确认范围。
- 引用不编造：书目信息不全时写已有的部分，并说明缺什么。
