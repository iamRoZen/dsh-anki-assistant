# 依据台账：规则 → 会话中的证据

来源：会话 `22bd9fc9-c7ee-4a0a-b9c7-c3961ac0353e`（同济高数第八版下册）。
图例：**强** = 会话内有明确要求与成品；**中** = 有做法但无逐条对照；**依据不足** = 只有结论。

## 用户反复要求的标准

| 规则 | 证据（turn） | 强度 |
|---|---|---|
| 答案必须拆成 `<ol><li>`，一条一个动作，不能一大段糊上去 | 13、14 两次要求；16 全册 212 张统一改写 | 强 |
| 条件、已知函数、公式左端留在 c1 内，不搬到正面 | 13 提出、16 确认「没有往正面搬」 | 强 |
| 问题用名词短语，不用自反性问句 | 22 回退问句风格（改回 62 张） | 强 |
| 名词短语必须**有主语、能独立看懂**，不许秃名词 | 23 明确要求，反面例子「部分和」「收敛半径」 | 强 |
| 公式用 `\(…\)`/`\[…\]`；校验 `math_issues=0` | 15、28 的校验结果 | 强 |
| 证明/推导卡打 `ai::derive` | 10、20、21 | 强 |
| 按节标题先查重，再每 5 张一批发送 | 25 明确写成规矩 | 强 |
| 复核员只交原文，产卡方逐字对，抓被省略的限定语 | 11、12（漏「\(z\) 有连续偏导」「\(f\) 连续」） | 强 |
| 进度表回填 | 2、9 | 中（流程，不是卡片规则） |

## 与旧 `anki_batch.py` 的关系

旧脚本能算 `cloze_mismatch` / `math_issues` / `md_issues`，但那是通用脚本；
本方案把其中能机器判的部分在 `validate.mjs` 用 JS 重写了（数学卡规则简单，不涉及字当量），
与旧脚本口径的差异记在 `checks.md`。
