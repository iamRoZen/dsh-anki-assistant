# 检查项：本方案 ↔ 会话实践

**执行方式**：本目录 `validate.mjs`（纯 JS，无 Python），由 `quality.validator.module` 加载；
`batch validate` 与 `card_write plan` 都会调用。缺模块时两个入口都报错，不算通过。

| 检查码 | 判什么 | 会话依据 |
|---|---|---|
| `CLOZE` | `{{c1::` 开头、`}}` 结尾、`}}` 后无尾巴 | 15、28：`cloze_mismatch=0` |
| `MATH_DELIM` | `\(\)`、`\[\]` 成对；无双反斜杠 | 15、28：`math_issues=0` |
| `MATH_ANGLE` | 公式内裸 `<` `>`（会被 HTML 吃掉） | 同上 |
| `MATH_BRACE` | 公式内 `}}`（提前结束挖空） | 同上 |
| `STEPS` | 有换行/分号/较长时必须 `<ol><li>` | 13、14、16 的改名要求 |
| `PROBLEM_FORM` | 名词短语、不以「？」结尾、不用自反式开头、不少于 6 字 | 22、23 |
| `MD` | 残留 `**`、反引号 | 28：`md_issues=0` |

## 与旧脚本的口径差异

| 项 | 说明 |
|---|---|
| 字当量 / 180 | 旧脚本算；本方案**不接管**（数学卡豁免）。`要点数` 允许留空 |
| 行超长（LONGLINE） | 旧脚本对列举卡算；数学卡本方案不判 |
| 篇章/覆盖率 | 旧脚本的 `REF` 需教材库；本方案只查引用格式 |
| 判重 | 由插件批次与 Anki 全局标签负责，不在本校验器 |

## 刻意不做的

- `NOBOLD` / `WEAKMARK`：数学卡重点是公式与条件，标粗策略不同，不做。
- 图表/插图检查：会话只试过一次，未形成规则。
