# qac-memory：问答挖空 · 带记忆提示

> 方案 id `qac-memory`｜当前版本以 `scheme get` 返回为准｜目标模型 `QAC 问答挖空 v4（国标引用）`

## 什么时候用

- 要背的是**一条独立的记忆线索**：一个定义、一组并列要点、一条机制链、一个数值阈值。
- 资料里讲这件事的是一段连续文字，能取到页与行。
- 反面：临表 + 分类 + 诊断 + 治疗混在一节里，先拆卡；纯计算题、推导题用别的方案。

## 资料入口

| 资料 | 怎么取 |
|---|---|
| 教材 PDF | `materials path=… pages=… keyword=…`，返回 `p<PDF页>:L<行>`；印刷页码写在定位里做对照 |
| 讲义 / 笔记 | 同样是文本，按小节标题找，不按概念词找 |
| 网页 | 用网页工具取正文，定位写 URL + 段落首句 |
| 已有卡 | `findNotes` 查首字段，改卡用 `mode=update` |

取原文的入口是**小节标题**（`【诊断】`、`适应证`、`治疗原则`），不是药名或病名。
按概念词过滤，会把别处的同类表述抓进来，拼出读起来像标准答案、原文却没有的东西。

## 五个模块怎么做

| 模块 | 这套方案的做法 |
|---|---|
| 资料整理 | 按小节标题取那几行，记 `p…:L…`；取不到就换段落或停下 |
| 问题集整理 | 一问一条线索，以「？」结尾；题干若来自真题就照抄；自拟要标"自拟" |
| 撰写答案 | 逐句对齐原文列可判分点；限定语、方向、阈值不改写 |
| 制作卡片 | 先骨架后填字，再压到考场长度；字段逐项见下 |
| 记忆指导 | 写进 `笔记` 字段：回忆起点 / 递推 / 最易漏的一步 |

## 字段与卡面

| 字段 | 角色 | 怎么写 | 卡面 |
|---|---|---|---|
| 问题 | 内容 | 单独可读、只问一条线索、以「？」结尾；不写选项，不出现答案里的词 | 正面 |
| 章节定位 | 定位 | `书名 ‖ 章 ‖ 节`，与目录层级一致 | 正面 |
| 要点数 | 元信息 | 答案去掉标签与挖空标记后的可见字数，写 `N字` | 正面 |
| 答案 | 内容 | 整段包在 `{{c1:: … }}`；序号 `<b>1.</b>` 段首；单行 ≤25 字 | 背面（挖空处隐藏） |
| 笔记 | 记忆提示 | 怎么背，两行以内；不复述答案 | 背面 |
| 引用 | 定位 | 书目 + `‖ p页:L起-止` | 背面 |

模板规范：挖空只能是 `c1`；答案必须 `{{c1::` 开头、`}}` 结尾；不要 Markdown（`**`、反引号），强调用 `<b>`。

## 格式选择：树还是表

- 原文是**并列或分层** → 序号树：`1.` / `1.1` 段首。
- 原文是**同一维度上的行列对照**（几类 × 几个属性）→ 表格，去掉一行就丢关系时尤其如此。
- 判断依据是原文长什么样，不是哪种更好看。

## 检查标准

机器规则（`scheme get` 里的 `quality.rules`，改了会出 v+1）：
问题以「？」结尾、答案以 `{{c1::` 开头且以 `}}` 结尾、答案长度上限、禁用 `**`、章节定位非空、
要点数等于答案实际可见字数。

人工判据（`quality.rubric`）：分支名必须来自原文标题；压缩不删层级、限定语、方向；
记忆提示只写怎么背。

## 正例

```
问题：哌唑嗪首次给药为什么安排在睡前？
章节定位：药理学（第10版） || 第十一章 肾上腺素受体阻断药 || 哌唑嗪
要点数：62字
答案：{{c1::<b>1.</b> 首剂易致晕厥，多为直立性低血压<br><b>2.</b> 给药：初始 0.5mg，
      睡前服，保持卧床数小时<br><b>3.</b> 目的：降低首次给药后的晕厥风险}}
笔记：先想"为什么要防"：首剂 → 血压骤降 → 晕厥；再记 0.5mg／睡前／卧床三个动作
引用：药理学（第10版）, 人民卫生出版社 ‖ p120:L6-9
```

## 反例

- **六条平铺、每条都带主语**：看着齐全，其实没有树——压缩时把层级压平了。
- **问题里出现答案的词**：等于把答案提前告诉一半。
- **`笔记` 复述答案**：记忆提示写成了第二份答案，背的时候反而多一条负担。
- **引用写"见教材某章"**：回查不到，等于没有依据。
- **要点数手填 `5字`**：格式对、数不对；规则会按答案实算核对。

## 验收

先做 2–3 张样卡请用户确认字段写法与压缩尺度，再批量。验收看四件事：
定位能回查、答案能逐点对照原文、记忆提示确实在教怎么背、要点数与答案一致。

## 已知局限

- 依赖目标模型已存在；换模型要另建方案。
- PDF 里的上下标会被拆成独立行（如 `α₁` 变成 `1 1`），含上下标的行定位会偏，需人工核对。
- 规则只管机械项，内容是否忠于原文仍需人判断。
